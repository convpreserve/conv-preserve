## Note on Call Counts
The initial generation (fu41) recorded exactly 1,092 more calls per set (e.g. 6,596 total vs 5,504 calls for Set 9) than the simple wrapper because it inadvertently captured the baseline calls. This difference is fully explained by the runner's logic:
- **1,092 calls** are made exactly once across all shapes by `reference_v100.py:build_heldout_bases()` during setup. This filters out baseline T1 findings prior to any mutant processing.
- The remaining calls strictly follow the formula: `loop_calls == activated_objects * 4`. In the mutant evaluation loop, `run_sets_heldout_v100.py` applies each activated mutant and calls `compare()` exactly four times per affected object (`F_base`, `F_dir_base`, `F_mut`, `F_dir`).
- The new Level A wrapper `_run_frozen_runner.py` accurately captures both the setup calls (since it patches `reference_v100.compare` directly alongside the runner's `compare`) and the loop calls, matching the true total counts.

Empirical count breakdown proving this formula across sets 9-14:
- Set 9: 1,092 setup + 5,504 loop calls
- Set 10: 1,092 setup + 6,124 loop calls
- Set 11: 1,092 setup + 6,244 loop calls
- Set 12: 1,092 setup + 7,372 loop calls
- Set 13: 1,092 setup + 9,660 loop calls
- Set 14: 1,092 setup + 8,060 loop calls
